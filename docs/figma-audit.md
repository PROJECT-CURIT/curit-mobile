# Figma Make 내보내기본 분석

분석 대상은 `프로토타입 - 앱.zip`과 Figma Make 파일 `Cnx9ZhlTf9xR6gURZ2Ezpx`이다.

## 확인 결과

- React/Vite 기반 웹 코드 48개와 390×844 기준 화면 36개가 포함되어 있다.
- 브랜드 기준은 `#4A6338`, Pretendard, 흰 배경, 5개 하단 탭이다.
- 크리에이터와 매장 운영자 역할에 따라 홈·관리 탭의 내용과 명칭이 달라진다.
- 상품 원본은 창작자가 관리하고, 매장은 공급 수량과 판매 상태를 관리한다.
- 굿즈는 즉시 수령, 작품은 전시 종료 후 수령한다.
- 정산 기준은 창작자 80%, 매장 10%, 플랫폼 10%다.

## 발견한 문제

1. 원본은 브라우저용 React/Vite 코드이므로 iOS·Android 네이티브 앱이 아니다.
2. 인증·작품·협업 상태가 `localStorage`와 하드코딩 데이터에 의존한다.
3. ZIP 원본은 `App.tsx`와 `OptionalSection.tsx`의 미사용 변수 때문에 `tsc --noEmit`이 실패한다.
4. 웹용 가짜 상태바·폰 프레임을 네이티브에 그대로 옮기면 실제 안전영역과 충돌한다.
5. OTP `000000`은 프로토타입 전용이며 실제 인증으로 사용할 수 없다.

## 이식 원칙

- 화면의 색상·밀도·간격·카드 구조는 기준 PNG와 비교한다.
- 상태바와 하단 안전영역은 기기의 실제 값을 사용한다.
- 서버 기능이 없는 화면은 프로토타입임을 코드 경계에서 명확히 한다.
- QR 상품은 기존 API를 실제 호출하고 구매는 기존 QR 웹으로 넘긴다.
- 로컬 저장소에는 역할·프로토타입 상태만 저장하고, 실제 토큰은 SecureStore로 이동한다.
