# 앱·QR 프로토타입 대조 결과

대조 대상:

- `프로토타입 - 앱.zip`의 Figma Make 코드와 36개 기준 화면
- `프로토타입 - QR 촬영 후.zip`의 방문객 구매 화면
- 현재 `curit-mobile`, `curit-api`, `curit-qr-web`

## 처음 확인된 핵심 누락

| 구간 | 기존 상태 | 문제 | 보완 결과 |
| --- | --- | --- | --- |
| AI 큐레이터 | 고정 문구와 샘플 카드 | 대화가 추천 결과를 바꾸지 않고 서버에 남지 않음 | 사용자별 대화와 추천 결과를 DB에 저장 |
| 추천 점수 | 하드코딩한 91%, 88% | 근거·재현성 없음 | 공간/작품 태그, 지역, 예산, 전시 구역, 재고를 가중 비교 |
| 추천 이유 | 없음 또는 한 줄 샘플 | 심사위원이 점수 산식을 검증할 수 없음 | 후보마다 적합도와 2~3개 근거 표시 |
| 매칭 전환 | 탐색과 협업관리가 분리 | 추천 후 실제 행동이 없음 | 추천 카드에서 협업 제안 RPC 호출 |
| 양방향 승인 | 정적 상태 카드 | 누가 언제 확정하는지 불명확 | 제안 → 크리에이터 승인 → 매장 최종 확정 상태 전이 |
| 협업 대화 | 샘플 2개 | 실제 참여자·협업과 무관 | 협업별 참여자 전용 메시지와 RLS 적용 |
| 홈/관리 | 고정된 수치·목록 | 실제 서버 상태와 불일치 | 서버 추천·협업·주문·정산 데이터로 교체 |

## QR 웹 비교

QR 프로토타입의 화면은 현재 구현에 대부분 반영되어 있고, 실제 구현은 프로토타입보다 범위가 넓다.

| 기능 | Figma ZIP | 현재 구현 |
| --- | --- | --- |
| 상품별 QR 주소 | 샘플 데이터 | 상품/협업별 고유 토큰 |
| 작품·작가·매장 정보 | 정적 | QR 발급 시점 스냅샷 |
| 구매 | 화면 시뮬레이션 | 토스 테스트 결제 승인 |
| 재고 | 로컬 숫자 | 승인 트랜잭션에서 원자적 차감 |
| 정산 | 표시용 | 주문별 80:10:10 원장 생성 |
| 재접속 | 로컬 | 고객 세션·주문번호로 서버 조회 |
| 반응형 | 모바일 중심 | 모바일 우선 + 데스크톱 중앙 프레임 |

따라서 QR 웹을 다시 만드는 것은 불필요했다. 이번 변경은 앱의 AI·매칭 단절을 해결하고 기존 QR 거래 흐름에 연결하는 데 집중했다.

## 추천 엔진의 정직한 정의

첨부 Figma Make의 챗봇도 외부 생성형 AI 모델을 호출하지 않고 태그 점수와 응답 규칙으로 동작한다. 현재 구현도 존재하지 않는 LLM 연동을 가장하지 않는다.

- 1차 필터: 공개 상태, 재고, 온보딩 완료 여부
- 적합도: 분위기/소재 태그, 지역, 예산, 설치 구역
- 설명: 점수에 기여한 조건과 협의가 필요한 조건을 문장으로 표시
- 대화: 질문 의도에 따라 추천/협업/정산 안내를 분기
- 데이터 축적: 대화, 추천 후보, 제안 및 상태 결과를 서버에 저장

후속 실제 AI 모델을 붙일 때도 LLM이 거래 가능 여부나 점수를 임의로 만들지 않고, 이 추천 결과를 설명하는 역할로 제한해야 한다.

## Figma 보조 기능까지 확장한 범위

핵심 거래 검증 이후에는 Figma Make에 있던 보조 기능도 정적 화면으로 남기지 않고 서버 데이터에 연결했다.

| 기능 | 실제 구현 |
| --- | --- |
| 크리에이터 프로필·DNA | 사진·소개·분야·지역·취향·협업 조건 저장과 단계형 온보딩 |
| 프로젝트 편집 | 기본 정보, 대표 이미지, 작품·굿즈 추가/수정/삭제, 공개 상태와 배분율 저장 |
| 커뮤니티 | 사진 소식 작성, 팔로우, 좋아요, 댓글, 공유 |
| 매장 프로필·취향 | 사진·고객층·예산·전시 구역 조회 및 수정 |
| QR 상품 운영 | 실제 QR 미리보기, 가격·재고·수령 방식·판매 상태 변경 |
| 수령 관리 | 주문 검색, 즉시 수령·예약 작품 분리, 전달 완료 처리 |
| 알림 | 협업 제안·상태 변경 알림과 읽음 처리 |

이 기능들은 거래 흐름과 분리된 장식이 아니다. 프로젝트·공간 데이터는 추천 입력값이 되고, 커뮤니티 반응과 QR 거래 결과는 이후 개인화 추천을 고도화할 행동 데이터로 사용할 수 있도록 사용자·콘텐츠·협업 ID를 기준으로 저장한다.
