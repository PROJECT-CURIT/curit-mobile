# 전체 흐름 QA — 2026-11-03

## 확인 완료

- Android release APK를 API 35 에뮬레이터에 설치해 크리에이터/매장 운영자 분기와 5개 하단 탭 이동을 확인했다.
- 크리에이터와 매장 홈, 추천 탐색, 협업 채팅 목록/상세, 협업·매장 관리, 마이 화면의 실제 기기 레이아웃을 확인했다.
- 가입·재전송 메일은 `curit://auth/callback`으로 복귀하고, 비밀번호 재설정은 `flow=recovery`를 유지한 뒤 앱에서 새 비밀번호를 저장하고 로그아웃한다.
- Supabase 운영 프로젝트의 Site URL은 `curit://auth/callback`, Redirect URL은 `curit://auth/callback`과 `curit://**`로 등록돼 있다.
- 배포 commerce API에서 상품 단가 55,000원, 수량 2개 주문에 클라이언트가 가짜 가격 1원을 보내도 서버가 110,000원으로 다시 계산하는 것을 확인했다. 테스트 주문은 결제 전 취소 처리했다.
- 토스 테스트 웹훅은 배포 Edge Function URL에 `PAYMENT_STATUS_CHANGED`, `CANCEL_STATUS_CHANGED` 이벤트로 등록돼 있다.
- 모바일 타입 검사·15개 단위 테스트·린트·웹 export, QR 웹 타입 검사·12개 단위 테스트·production build·format 검사를 통과했다.

## 외부 계정/계약이 있어야 끝나는 항목

- Supabase 기본 메일 발송기는 시연용 제한이 있으므로 임의의 심사위원 이메일까지 안정적으로 인증하려면 별도 SMTP 계정과 발송 도메인이 필요하다. 앱 콜백과 재설정 코드는 완료됐지만 SMTP 공급자 자격 증명은 저장소에 만들 수 없다.
- 현재 토스 계정은 `개발 연동 체험 상점`이다. 문서용 테스트 키로 테스트 결제창까지 열리며 실제 돈은 결제되지 않는다. 사용자 카드/간편결제 인증을 대신 입력할 수 없으므로 승인 완료 1건은 계정 소유자가 테스트 결제창에서 인증해야 한다.
- 체험 상점에는 MID가 없어 `TOSS_EXPECTED_MID`를 설정할 수 없다. 웹훅 보안 키 검증은 활성화돼 있다. 실제 상점 계약 후 MID가 발급되면 MID 검증도 켜야 한다.
- 판매대금 지급대행은 별도 토스 계약·판매자 KYC가 필요하다. 현재 주문 결제 후 재고 차감과 정산 원장 생성까지 구현돼 있고 실제 계좌 지급은 비활성 상태다.
