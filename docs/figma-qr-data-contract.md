# QR 상품 관리와 데이터 계약

## 권한

- 크리에이터는 자신의 원본 상품을 등록·수정·삭제한다.
- 매장은 확정 협업의 QR 판매 정보를 생성하고, 공급량 범위 내 판매 가능 수량을 수정한다.
- 합의한 상품명·단가·상품 유형·수령 조건·상품 설명은 매장이 임의 변경하지 않는다.
- QR 판매 중단은 고객 대상 새 주문을 차단한다. 기존 주문·고객 전달·정산 기록은 삭제하지 않는다.
- 동일 상품을 재등록하면 같은 상품 ID와 남은 수량을 유지한다.
- 진행 중인 협업이나 미완료 주문이 있는 원본 상품은 기존 삭제 보호를 따른다.

## 원본 상품과 QR의 식별

신규 등록 상품은 `프로젝트ID-p상품ID` 형식이다. 목록에서 앞 상품을 삭제하거나 순서가 바뀌어도 QR 식별자가 바뀌지 않는다. 기본 상품의 `0-0` 등 기존 ID는 유지한다.

기존 순번형 상품과 주문은 호환 경로로 읽는다. 매장 주문은 협업 요청 ID를 함께 사용하며, 작가 판매 내역은 같은 상품 ID에 연결한다.

## 입력값으로 QR 화면 만들기

`src/qrPurchase.ts`의 API:

- `buildQrSnapshot`: 확정/전시 중인 협업, 매장, 프로젝트, 작가, 상품, 주문 정보를 받아 QR 데이터를 생성한다.
- `parseQrSnapshot`: 내보낸 JSON 또는 URL의 `curit` 데이터에서 동일 구조를 읽고 필수 정보·유형·수량·날짜를 검증한다.
- `qrSnapshotUrl`: 동일 데이터를 현재 링크 형식에 담는다.
- `qrProductMatchesLine`, `remainingQrSupply`: 상품 고유 ID와 협업 수량을 기준으로 연결한다.

매장 QR 판매 설정의 **QR 정보 미리보기**는 고정 샘플 없이 생성한 데이터만 렌더링한다. **QR 데이터 내보내기**는 같은 데이터를 JSON 파일로 저장한다. 새 QR 웹앱은 이 데이터 계약과 검증 함수를 적용해 화면을 구성할 수 있다. 기존 게시 QR 웹앱의 파서나 주문 연결은 이번 변경에 포함하지 않는다.

### 포함 정보

- 매장: 이름, 공개 주소, 문의 연락처, 운영 시간
- 작가: 활동명, 아이디, 소개, 작업 이야기, 지역, 분야, 프로필 사진, SNS, 포트폴리오, 분위기, 색감, 협업 목적
- 프로젝트: 제목, 콘셉트, 대표 이미지, 태그, 합의 당시 전시 지역·선호 공간·설치 조건
- 상품: 고유 ID, 이름, 합의 단가, 판매 가능 수량, 사진, 소개, 구성, 소재, 관리 안내, 수령 방식, 전시 종료일
- 운영: 매장 ID, 협업 ID, 준비/판매/중단 상태

가입 이메일·비밀번호·인증 자료·고객 명단은 QR 데이터에 포함하지 않는다.

## 수정·중단 시 주의

데이터에 포함된 내용은 생성 시점의 스냅샷이다. 매장 연락처, 판매 가능 수량, 공개 프로필 등이 바뀌면 최신 데이터를 다시 내보내거나 QR 링크를 재발급한다.

서버 없는 URL 스냅샷은 이미 배포한 옛 QR을 원격으로 즉시 폐기할 수 없다. 나중에 연결할 때 주문 확정 단계에서 현재 계정·협업 상태·판매 중단·재고·합의 금액을 다시 확인해야 한다. 현재 앱의 주문 검증은 중단 상품과 종료/미확정 협업, 재고 초과, 금액 불일치를 거부한다. 이 구조가 실제 금융 결제 인증이나 서버 권한 검증을 대신하지는 않는다.

## 검증

`node tests/qr-data-contract.cjs`

상품 삭제/순서 변경 시 ID 유지, 다른 상품 오매칭 방지, 기존 주문의 수량 차감, JSON/URL 왕복, 잘못된 정보·날짜 차단, 판매 중단 상품의 새 주문 거부를 검사한다.

별도 브라우저 검사에서도 JSON 다운로드·데이터만 사용하는 로컬 미리보기·판매 중단 후 기존 수령 유지·재등록 후 ID/재고 유지를 확인했다. 신규 두 계정의 굿즈/전시 작품 협업·주문·전달·정산도 재검증했다.
