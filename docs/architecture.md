# CURI:T 모바일 구조

## 선택한 환경

- Expo SDK 58 / React Native 0.88 / React 19
- Expo Router: 네이티브와 웹의 동일한 라우팅·딥링크 기반
- TypeScript strict: Figma Make 내보내기본의 암묵적 타입 오류를 제거
- Pretendard 로컬 번들: 플랫폼과 네트워크 상태에 상관없이 동일한 한글 조판
- Supabase Auth: 이메일 가입·로그인·비밀번호 재설정과 세션 갱신
- SecureStore: 네이티브 인증 세션을 분할 암호화 저장하고, 웹은 브라우저 저장소 사용
- Supabase Postgres/RLS: 프로필·프로젝트·매장·추천·협업·커뮤니티 데이터 영구 저장과 참여자 권한 분리
- Supabase Storage: 프로필·작품·매장·커뮤니티 이미지 영구 저장
- `react-native-qrcode-svg`: 상품별 웹 주소를 실제 QR로 표현
- `expo-web-browser`: 방문객 구매 화면을 앱 외부의 안전한 브라우저 세션으로 실행

## 런타임 경계

```text
CURI:T Mobile
  ├─ Supabase Auth/Postgres/Storage ──> 회원·작품·공간·추천·협업·커뮤니티
  ├─ Commerce Edge Function ─────────> QR 발급·주문·재고·수령·정산
  └─ /?qr={opaqueToken} 열기 ────────> curit-qr-web
                                       └─ 상품·가격·재고를 서버에서 재조회
```

앱은 가격이나 재고를 QR URL에 넣지 않는다. QR에는 추측하기 어려운 토큰만 담고, 구매 가격·재고·수령 방식은 API 응답을 기준으로 한다. 이는 앱과 QR 웹의 표시가 달라지는 문제와 클라이언트 가격 변조를 막기 위한 구조다.

## 상태 소유권

- 창작자: 원본 작품·굿즈, 가격, 작품 설명
- 매장: 협의된 공급 수량, 판매 일시정지·재개, 현장 수령 상태
- 서버: 주문 당시 가격·재고 스냅샷과 정산 기준
- QR 웹: 방문객 탐색·본인확인·결제·주문 확인

회원·작품·매장·추천·협업·커뮤니티 데이터는 Supabase에 저장되고 RLS로 역할과 참여자 범위를 제한한다. QR 발급 이후의 공개 상품 조회, 주문, 재고 차감, 현장 수령과 정산 원장은 Commerce Edge Function이 담당한다. 데모 모드의 샘플 데이터는 심사용 화면 확인에만 사용하며 실제 계정 데이터와 분리한다.

QR 조회 수는 QR 웹이 만든 무작위 익명 식별자를 서버에서 해시해 `상품·방문자 해시·한국 날짜` 기준으로 중복 제거한다. IP 주소나 사용자 에이전트는 저장하지 않으며, 앱은 운영 QR별 누적 순방문 수를 합산해 매장 성과에 표시한다.
