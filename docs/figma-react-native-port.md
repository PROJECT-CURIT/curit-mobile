# CURI:T — React Native 이식의 첫 번째 지침

이 저장소는 **실행 가능한 React 웹 원본**이다. React Native 앱 자체가 아니다.
목표는 재디자인이 아니라 현재 화면·문구·동작의 충실한 이식이다.

## 다른 AI에 그대로 붙일 요청문

> 이 저장소의 CURI:T 웹 앱을 React Native 앱으로 이식해 주세요.
> 먼저 REACT_NATIVE_PORT.md와 docs/native/PORTING_SPEC.md, docs/native/source-manifest.json을 읽으세요.
> src/App.tsx와 각 화면 컴포넌트, src/index.css가 디자인과 동작의 원본입니다.
> docs/native/reference의 최신 실행 화면·레이아웃 측정값을 대조하세요.
> 디자인을 개선하거나 새로 해석하지 마세요. 화면 순서, 섹션 순서, 여백, 글자 크기,
> 색상, 둥근 정도, 이미지 비율, 버튼 위치, 탭 개수, 기본 접힘 상태를 유지하세요.
> 네이티브 기본 헤더·탭 바·버튼 스타일을 자동 적용하지 마세요.
> DOM·브라우저 API만 네이티브 어댑터로 교체하고 상품 ID·협업 상태·수령·정산 규칙은 보존하세요.
> 웹 원본 파일을 덮어쓰지 말고 별도 native 프로젝트에서 작업하세요.
> 삭제된 옛 화면과 입력 항목을 복원하지 마세요.
> 화면별 구현을 원본 캡처와 비교한 후 차이·테스트 결과를 보고하세요.
> 원본 정보나 폰트가 부족하면 임의 대체하지 말고 필요한 내용을 명시하세요.

## 반드시 함께 전달할 파일

1. 이 문서와 `docs/native/` 전체
2. `src/` 전체 — `App.tsx` 한 파일만 주면 화면·스타일·데이터 함수가 빠진다.
3. `package.json`, `tests/`, 기존 `docs/qr-data-contract.md`
4. 사진/폰트 등 네이티브 대상에서 필요한 정식 에셋

`src/imports/`의 옛 업로드 이미지는 실행 코드에서 참조되지 않는 역사 자료다.
현재 디자인과 충돌하면 최신 실행 캡처와 소스가 우선이다.

## 한 파일로 전달하고 싶을 때

```sh
node scripts/create-native-handoff.mjs
```

`native-handoff/CURIT_NATIVE_SOURCE.md`에 지침과 현재 실행 소스를 파일별 코드 블록으로 묶는다.
이를 AI에 올리고, 바이너리 참고 화면은 `docs/native/reference/`를 함께 전달한다.
이 묶음은 파일 내용을 설명하는 문서이지 한 파일로 실행하는 JS 번들이 아니다.
스크립트는 `.env`, 사용자 저장 데이터, `.git`, `node_modules`, `dist`, 플랫폼 내부 파일을 포함하지 않는다.
현재 화면에서 쓰지 않는 옛 업로드 이미지도 전달 묶음에서는 제외하며 원본 저장소에는 보존한다.

## 이식 완료 판정

- 동일한 390 × 844 기준에서 원본과 같은 배치·타이포그래피를 확인한다.
- 원본의 현재 동작을 먼저 복제하고, 리팩터링/백엔드 도입/새 디자인은 별도 단계로 한다.
- iOS/Android Safe Area, 키보드, 글꼴, 뒤로가기를 실제 기기/시뮬레이터에서 확인한다.
- QR 외부 주문 연결은 별도 작업이다. JSON 기반 QR 미리보기·판매 중단·기존 주문 보존은 이식한다.

문서와 코드만으로 **다른 AI의 픽셀 단위 동일성을 보장할 수는 없다.**
원본 지침·측정값·캡처를 함께 제공하고 화면 비교를 완료 조건으로 삼는 것이 핵심이다.
