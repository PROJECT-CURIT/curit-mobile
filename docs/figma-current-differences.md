# Figma Make와 현재 구현의 차이

비교 기준은 `docs/figma-reference/`에 보관한 Figma Make 36개 화면이다. 아래에는 **같은 부분을 제외하고 차이만** 기록한다.

## 이번 QA에서 구현해 없앤 차이

| Figma 기준 | 기존 차이 | 현재 반영 |
|---|---|---|
| 07 크리에이터 프로필 | 등록 프로젝트 영역과 프로젝트 상세 연결이 없었음 | 프로필 하단에 공개 상태·제목·콘셉트가 포함된 프로젝트 카드를 추가하고 상세 화면에 연결 |
| 09 크리에이터 프로젝트 | 심사용 샘플에는 상품이 1개뿐이라 복수 상품 화면을 검증하기 어려웠음 | 굿즈와 전시 작품 샘플을 각각 추가해 복수 상품·수령 방식·상세 펼치기를 검증 |
| 25–27 프로젝트·상품 사진 | 형식 오류가 뒤늦게 표시되거나 사진 선택 위치에서 보이지 않았고, 저장된 사진을 제거해도 주소가 남았음 | 작품 추가·수정 시 입력 폼 위치를 보여준다. 사진 선택 직후 JPG·PNG·WebP와 5MiB 한도를 검사하고, 오류 시 이전 사진과 입력값을 유지한다. 사진 삭제를 저장하면 상품에서 이미지 연결을 제거한다. |
| 31 매장 사진 | 한 장이 없으면 전시 구역 단계로 넘어갈 수 없었음 | 대표 사진 등록과 사진 없이 계속을 제공한다. 등록 후 프로필에서 사진만 추가·삭제할 수 있고, 창작자 추천에는 사진이 비어 있는 상태를 표시한다. |
| 15·30 매장 공간 취향 | 등록과 수정의 선택지가 달랐고 공간 색감이 없었음 | 두 화면에서 같은 선택지를 사용하고 예전에 저장한 항목도 표시한다. 색감은 추천 이유와 탐색 필터에 연결했다. 예산 범위 검증과 하단 저장을 추가했다. |
| 크리에이터 마이 활동 요약 | 프로필과 설정 메뉴만 표시해 진행 중인 협업과 정산 예정액을 한눈에 확인할 수 없었음 | Figma Make 변경 기록에 따라 프로필 아래에 두 수치를 추가했다. 승인 대기부터 전시 중까지를 집계하며, 정산 원장의 예정·지급 준비 건에서 크리에이터 몫을 합산한다. |
| 10 크리에이터 협업 관리 | 진행 중·완료·예상 정산만 표시해 제안·출고·전시 단계가 구분되지 않았고 프로젝트 진입이 중복됐음 | 협업 상태 수치와 판매·정산을 표시한다. 작품·재고 수정은 마이의 내 전시 프로젝트에서 연다. |
| 11 크리에이터 정산 | 정산 원장 목록만 있고 상태 필터와 거래 상세가 없었음 | 전체·정산 대기·정산 완료·보류/취소 필터, 결제액·배분액 상세, 해당 협업 이동을 추가 |
| 12 탐색 검색 | 검색과 필터가 홈 추천 상위 6개에만 적용됐고, 작품·작가 검색은 처음 불러온 50개에 한정됐음 | 홈 추천과 탐색의 조회 범위를 분리한다. 탐색은 공개 후보를 여러 페이지로 불러와 작품명까지 검색하고, 결과는 8개씩 보여준다. 매장과 작품·작가 탭의 검색어를 각각 유지한다. |
| 09·12 전시 프로젝트 상세 | 작품·작가 카드와 매장 추천에서 프로젝트의 이야기와 등록 작품을 열 수 없었음 | 두 경로에서 공통 상세 화면을 연다. 작품의 크기·소재·수령 방식을 확인하고 돌아와도 검색어를 유지한다. 편집과 배분 정보는 소유자 화면에 표시한다. |
| 17 매장 운영 | QR 조회·판매·예상 정산만 있어 협업 운영 단계가 보이지 않았음 | 제안 확인·전시 준비·전시 중 상태를 추가하고 기존 매출 지표를 별도 영역으로 유지 |
| 19 매장 QR 판매 설정 | QR 관련 동작이 여러 줄의 버튼으로 흩어져 있었음 | 원본의 변경 기록에 맞춰 QR 미리보기·주소 복사·구매 화면 열기를 한 카드로 묶었다. 수량 저장 결과와 판매 중단 확인은 별도로 보여준다. |
| 21 주문·현장 수령 | 상품 사진과 수령 시점이 카드에 없었고, 알림은 수령 대기 목록만 열었음 | 상품 사진·수령 안내·접을 수 있는 확인 안내·QR 판매 설정을 연결했다. 원격 주문 알림과 주문 ID가 연결된 내 소식 항목은 해당 주문의 현재 상태를 바로 연다. |
| 22 매장 판매·정산 | 주문별 정산 원장만 표시돼 같은 전시에서 몇 개를 판매했는지 확인할 수 없었음 | 전시별 판매·정산 탭을 나눴다. 매장 결제 완료 주문과 정산 원장을 연결해 전시별 판매 수량과 정산 예정액을 표시한다. 헤더의 수령 아이콘으로 주문 화면을 연다. |
| 협업 채팅방 | 프로젝트·작품 수량·배치 조건이 대화보다 먼저 길게 노출됐음 | 대화 중심 화면으로 바꾸고 조건은 기본 접힘 상태의 `협업 요약` 안에서만 관리하도록 분리 |
| 크리에이터/매장 마이 | 프로필·정산 바로가기와 같은 기능이 메뉴에 중복되고 매장에는 기획되지 않은 분기 관리 메뉴가 있었음 | 프로필·정산 중복과 분기 관리 메뉴를 제거하고 Figma의 핵심 메뉴 순서와 명칭에 맞춤 |
| 프로필·DNA·인증의 장애 상태 | 정적인 프로토타입에는 조회 실패·재시도·늦은 저장 응답의 동작이 정의되지 않음 | 기존 정보를 읽지 못하면 편집 대신 오류와 재시도를 표시한다. 저장된 이전 선택값을 유지하고, 늦은 프로필 저장 결과가 다른 계정이나 떠난 화면에 적용되지 않도록 구분한다. |

## 의도적으로 다르게 구현한 부분

| Figma Make | 현재 구현 | 다른 이유 |
|---|---|---|
| 휴대전화 번호와 고정 인증번호를 이용한 가입 시연 | Supabase 이메일·비밀번호 가입과 실제 이메일 인증 | Figma의 인증번호는 화면 시연용이며 실제 본인 확인이 아니다. 가짜 SMS 인증을 복제하지 않았다. |
| 굿즈 등록과 작품 등록이 별도 화면 | 상품 유형을 선택하는 하나의 동적 등록 폼 | 중복 입력 화면을 줄이되 유형별 소재·크기·관리·수령 필드는 그대로 제공한다. |
| 프로젝트 최종 확인이 별도 화면 | 3단계 편집 흐름의 마지막 단계로 통합 | 기능은 같고 뒤로가기 및 수정 흐름을 단순화했다. |
| 휴대전화 목업 상태바와 고정 하단 여백 | 네이티브 Safe Area와 실제 기기 하단 영역 사용 | iOS·Android 기기별 노치와 제스처 영역에 대응하기 위해서다. |
| 정적인 AI 대화 예시 | 공간·작품 조건 필터, 태그 점수, 추천 사유, 선택·거절 결과 저장 | 실제 데이터로 다시 추천할 수 있도록 규칙·데이터 기반으로 구현했다. 외부 생성형 LLM을 연결했다고 과장하지 않는다. |
| QR 구매 시연 화면 | 현장 상품은 고유 QR과 계좌이체 안내, 협업 주문은 토스 테스트 결제·주문·재고·정산 원장 | 실제 카드 청구·송금·지급은 실행하지 않는다. 이체 안내 열기와 입금 완료를 구분한다. |
| Figma에 없는 계정·알림·검증 화면 | 계정 관리, 활동/매장 인증 자료, 알림 내역 추가 | 실제 서비스 운영과 심사 시연에 필요한 보완 기능이다. |

## 아직 남은 차이와 이유

| 남은 차이 | 현재 상태 | 완료에 필요한 것 |
|---|---|---|
| 실제 휴대전화 SMS 인증 | 이메일 실인증으로 운영 | Supabase Phone Auth와 SMS 사업자 계약·발신 설정. 출시하지 않는 본선 시연에는 필수 아님. |
| 생성형 LLM 대화 | 질문 선택과 조건 기반 추천은 동작 | 모델 제공자, 비용 한도, 프롬프트·안전 정책을 확정해야 한다. 현재 핵심 매칭은 LLM 없이도 재현 가능하다. |
| 약관 동의 전문 | 가입·인증은 동작하지만 별도 약관 체크 화면은 없음 | 이용약관·개인정보처리방침의 실제 문안과 동의 버전을 확정해야 한다. 임의 문구를 법적 동의로 표시하지 않았다. |
| 실물 iOS 푸시 수신 | Android APK와 앱 내 알림 흐름은 확인 | Apple Developer/APNs 자격 증명과 실제 iPhone이 필요하다. |

## 결론

현재 남은 차이는 단순 UI 누락이 아니라 외부 인증·정책·운영 규칙이 필요한 항목이다. 본선 시연의 핵심 흐름인 `프로젝트 등록 → AI 추천 → 협업 승인 → QR 결제 → 주문·재고 → 정산`은 연결되어 있으며, 이번 QA에서 Figma의 프로필·관리·정산 화면에 있던 실질적인 누락을 보완했다.

## 협업 작품 선택과 전시 확정

- 매장 운영자는 협업 요약에서 전시할 작품만 선택하고 보유 재고 안에서 수량을 제안한다. 크리에이터는 제안받은 작품과 수량을 확인한다. 전시 확정은 모든 제안 수량이 확인된 뒤 가능하다.
- 작품별 선택과 수량을 별도 행으로 배치했다. 전시를 확정하면 같은 대화에서 해당 전시의 QR 상품 관리로 이동한다. Android 뒤로가기는 QR 상품 목록을 거쳐 해당 대화로 돌아간다.
- 프로토타입 34~36의 희망 시작일·종료일, 작품 선택과 수량 확인, 전시 확정 및 QR 판매 흐름을 반영했다. 날짜는 숫자 키보드로 입력한다. 전시 기간은 창작자가 새 날짜를 확인한 후 확정할 수 있고 QR 발급 이후에는 고정된다.
- 프로토타입 36의 전시 준비 확인은 실제 판매를 여는 상품별 QR 설정에 배치했다. 새 QR은 판매 준비 상태로 발급된다. 매장 운영자가 상품 진열과 QR 가격·재고·수령 안내를 확인하면 해당 상품의 판매를 시작할 수 있다.
- Figma Make 앱의 원격 변경 기록에서 QR 액션 통합과 협업 관리의 중복 프로젝트 버튼 제거를 확인했다. 실제 앱의 판매 중단은 새 주문 접수만 멈춘다. 기존 주문은 수령 관리에 남는다.
